# ⚽ Football Analysis — YOLO Tracking, Team Assignment & Match Stats

Detect and track **players, referees, goalkeepers and the ball** with YOLO + ByteTrack,
assign players to teams by shirt colour (K-Means), measure **ball possession**,
compensate **camera movement** (optical flow), convert pixels → meters
(perspective transform), and report **per-player speed & distance** — then
explore it all in an interactive **Streamlit app** that exports an annotated
video, a BEFORE/AFTER comparison clip, and a stats CSV.

## ✨ What it does

| Feature | How |
|---|---|
| Player / referee / ball detection + tracking | YOLO (`model/best.pt`) + ByteTrack (`trackers/`), goalkeeper merged into player class, ball gaps interpolated |
| Team assignment | K-Means on jersey pixels (`team_assigner/`) → Team 1 / Team 2 colours |
| Ball possession | Nearest-player assignment (`player_ball_assigner/`) → per-team control % over time |
| Camera-motion compensation | Lucas-Kanade optical flow (`camera_movement_estimator/`) subtracted from positions |
| Pixels → meters | Pitch-corner perspective transform (`view_transformer/`) |
| Speed & distance | 5-frame window @ 24 fps → km/h + cumulative meters (`speed_and_distance_estimator/`) |
| One-click web UI | `app.py` — upload clip → watch progress → annotated mp4 + BEFORE/AFTER mp4 + stats table/CSV |

## 🧠 How the pipeline works

```
video frames
  → Tracker (YOLO detect → ByteTrack → interpolate ball)
  → CameraMovementEstimator (optical flow, adjust positions)
  → ViewTransformer (pitch homography, px → meters)
  → SpeedAndDistance_Estimator (km/h, meters)
  → TeamAssigner (K-Means shirt colours → team 1/2)
  → PlayerBallAssigner (possession → team control %)
  → draw: ellipses + IDs, possession triangle, ball triangle,
          control panel, camera readout, speed/distance labels
  → analyzed mp4 + BEFORE/AFTER comparison + stats
```

* `trackers/tracker.py` — detection, tracking, interpolation, all drawing.
* `team_assigner/` — 2-stage K-Means (jersey vs background, then team A vs B).
* `camera_movement_estimator/` — tracks pitch-edge features frame-to-frame.
* `view_transformer/` — ⚠️ **calibrated to the demo camera angle.** For your own
  footage, update `pixel_vertices` in `view_transformer/view_transformer.py` to
  your pitch corners or speed/distance will be off.
* `player_ball_assigner/` — 70 px foot-to-ball threshold (`max_player_ball_distance`).
* `speed_and_distance_estimator/` — `frame_window=5`, `frame_rate=24`.

## 🚀 Quickstart (local)

```bash
cd football_analysis
python -m venv env && env\Scripts\activate        # Windows
# source env/bin/activate                          # macOS/Linux
pip install -r requirements.txt
```

**1. Model weights** — the detector is gitignored, so add it once:

* Train your own: `development_and_analysis/training/football_training_yolo_v5.ipynb`
  (Roboflow `football-players-detection` → `yolo task=detect mode=train …`), then
  copy the result to `model/best.pt`; **or**
* Reuse an existing `best.pt` with classes
  `player / referee / ball / goalkeeper` → place at `model/best.pt`.

> A generic COCO model (e.g. `yolov8n.pt`) will *not* work with the full
> pipeline — the tracker looks up football class names and possession/speed
> stages expect them. The app shows a clear error in that case.

**2a. Streamlit app (recommended):**

```bash
streamlit run app.py
```

Upload a clip (or use the demo) → **Run analysis** → you get, in one pass:

1. 🎬 Annotated video (`st.video` + download `.mp4`, H.264 so it plays in browsers)
2. ↔️ **BEFORE/AFTER comparison clip** — auto-built side-by-side after analysis,
   with downloads for the mp4 + a poster JPG
3. 📊 Ball-control metrics, per-player speed/distance table + chart, stats CSV

Sidebar options: model path (or upload `best.pt`), detection confidence,
compute device (auto/CPU/GPU), clip-length cap, camera/speed toggles.
Re-running the same video + settings serves disk-cached results instantly.

**2b. CLI batch run:**

```bash
python main.py --input 08fd33_4.mp4 --model model/best.pt \
  --out output_videos/output_video.mp4 --max-seconds 0
# → output_videos/output_video.mp4 (+ stubs/ cache for fast re-runs)
python make_before_after.py --input 08fd33_4.mp4 \
  --analyzed output_videos/output_video.mp4 \
  --out assets/before_after.mp4 --poster assets/before_after_poster.jpg \
  --max-seconds 10
```

## ☁️ Publish the Streamlit app (Community Cloud)

The repo is already packaged (`app.py`, `requirements.txt`,
`.streamlit/config.toml`). `model/`, `input_videos/`, `output_videos/` stay out
of git; weights reach the cloud via upload or URL:

1. **Push to GitHub**
   ```bash
   git add app.py make_before_after.py requirements.txt .streamlit/ assets/ 08fd33_4.mp4 README.md .gitignore
   git commit -m "Add Streamlit app + BEFORE/AFTER + docs"
   git push origin master   # repo: Seronic2001/football_analysis
   ```
2. **Deploy** — [share.streamlit.io](https://share.streamlit.io) → *New app* →
   repo `Seronic2001/football_analysis`, branch `master`, main file `app.py` → *Deploy*.
3. **Weights** — `model/best.pt` is 172 MB, over GitHub's 100 MB file limit, so
   it stays out of git (see `.gitignore`) — pick one:
   * *Easiest:* open the deployed app → sidebar → **upload `best.pt`** (per session), or
   * *Persistent:* attach it to a GitHub Release (releases allow GB-size files):
     web: repo → Releases → *Draft a new release* → tag `v1` → drag-drop
     `model/best.pt` as a binary → Publish. (No `gh` CLI needed.)
     ```bash
     # equivalent with the GitHub CLI:
     gh release create v1 model/best.pt --title "v1" --notes "finetuned football YOLO weights"
     ```
     then app *Settings → Secrets*:
     ```toml
     MODEL_URL = "https://github.com/Seronic2001/football_analysis/releases/download/v1/best.pt"
     ```
     The app downloads it once to `model/best.pt` automatically.

Free-tier tips: keep clips ≤ 20 s (sidebar slider), prefer 720p uploads, leave
`opencv-python-headless` in requirements (no system packages needed).

## 📊 Reading the outputs

* **Ellipses + IDs** — player trackers, coloured by team; yellow = referee.
* **Red triangle over player / green over ball** — current possession holder + ball.
* **Team 1/2 Ball Control %** — cumulative share of possessed frames (bottom-right).
* **Camera Movement X/Y** — per-frame optical-flow compensation (top-left).
* **`xx km/h` / `yy m`** — per-player speed + cumulative distance under each ellipse.
* **Stats tab (app)** — max/avg speed and distance per player ID + CSV download.

## ⚡ Performance (same model, same pixels — just cheaper)

Measured on the demo clip, 250 frames @ 1080p (8-core CPU + GTX 1050):

| | Before (in-RAM) | After (streaming) |
|---|---|---|
| Peak RAM | **~5.3 GB** | **~1.0 GB** (flat vs clip length) |
| Wall time (GPU) | ~50 s | ~40–46 s |
| App re-run, same settings | full recompute | **instant (disk cache)** |
| Output pixels | — | bit-identical overlays (verified: mean frame diff ~1.0 = x264 rounding only) |

How, without touching accuracy (same weights, same 640 imgsz, every frame):

* **`pipeline.py`** — frames stream in batches; only track dicts (KBs) accumulate.
  Drawing + H.264 encode fuse into one pass with a single frame copy
  (was: 3 full-clip copies). Used by both `main.py` and `app.py`.
* **Faster x264 preset** (`veryfast` + `zerolatency` tune) — encode was 18 s alone.
* **Log spam off** (`verbose=False`), tunable `--conf/--batch-size/--device`.
* **Deterministic teams** — fixed K-Means seeds, so runs are reproducible and cacheable.
* **Stubs + app cache** — `stubs/` skips detection/camera on CLI re-runs;
  the app hashes (video + weights + settings) and serves saved mp4s instantly.

Honest negatives (measured, not assumed):

* **ONNX CPU: ~2x slower than PyTorch CPU** for this model here
  (~1.7 s vs ~0.8 s/frame; GPU does ~0.05 s) — `export_onnx.py` stays as
  an opt-in experiment, nothing auto-uses it.
* **OpenVINO: also slower** (0.9 s/frame CPU) — not wired in.
* **Streamlit Cloud is CPU-only** (~0.8 s/frame detection): a 20 s clip takes
  ~7 min there on first run — fine for a demo, and RAM stays safe now.

## ⚠️ Limitations & next ideas

* `ViewTransformer` pitch corners are hardcoded for the demo angle — recalibrate
  per stadium/camera, or auto-detect pitch lines.
* Team override `player_id == 91 → team 1` in `team_assigner.py` is a demo hack —
  remove for new footage.
* Ball interpolation fills gaps linearly; long occlusions still drift.
* Fixed 24 fps assumption in speed math — resample or read true fps per clip.
* Ideas: pass maps, heatmaps, formation detection, Streamlit caching of stubs,
  GPU flag, multi-match aggregation.
